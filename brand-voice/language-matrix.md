# Language Matrix

Which language Learnish uses, for which audience, on which channel. Pairs with the [voice guide](voice-guide.md) — voice is *how* we sound; this is *which language* we sound it in. Learnish sells to parents in Uzbekistan / Central Asia (Tashkent first, then regions), so language fit is part of the "local trust" moat.

## Default policy

Learnish runs **three primary languages**, in priority order:

1. **Uzbek** — the default lead for parent-facing first-touch and local trust.
2. **English** — a first-class language, not just in-product: it signals quality/global standards to many parents and is what teens expect for tech/skills.
3. **Russian** — a primary language for the large RU-preferring audience across Tashkent and the regions.

- **All three are "primary"** — core assets (landing pages, key campaigns, product UI) should ship in UZ, EN, and RU. **Uzbek is the default lead for parent first-touch** (decided); produce EN + RU alongside.
- **Pick the lead per audience, don't force all three everywhere.** A hyper-local workshop flyer leads in the district's language; a teen coding course leans English; a regional parent email may lead Russian or Uzbek. The order above is the tiebreaker, not a rule to cram three languages onto every asset.
- **Kid-facing tone adjusts by age, not just language:** simpler UZ/RU for 5–12; teens 13–17 tolerate and often prefer English for tech/skills ("Python," "startup," "design").

### Uzbek script

- **Latin Uzbek is the default** for marketing and product UI (decided) — it's the standard for younger parents and digital contexts.
- Offer **Cyrillic Uzbek** only where a specific older audience, venue, or partner expects it — case-by-case, not a parallel default.

## Channel matrix

Default priority is **Uzbek → English → Russian**; "Lead" is the language a piece is authored in first, "Also produce" lists the others that core assets should be localized into.

| Channel | Lead | Also produce | Notes |
|---|---|---|---|
| Workshop flyers / on-the-ground (the acquisition engine) | Match the district | Mirror as needed | Hyper-local — lead in the language of that neighborhood/venue |
| Landing pages | Uzbek | English, Russian | Mirror the core value prop and the free-workshop / free-account CTA in all three |
| App & courses (UI) | Uzbek | English, Russian | All three first-class; English used for skill terms teens expect; content age-tiered |
| Instagram / TikTok / short-form | Match the audience | Code-switch OK | UZ/EN/RU as the segment dictates; natural code-switching is fine, hype is not |
| Telegram (community + parent comms) | Uzbek | English, Russian | Mirror key posts; let community threads be multilingual |
| Email / lifecycle | Segment by preference | — | Capture language preference at signup; send in the parent's chosen language |
| Ambassador / teacher recruiting | Match the campus/district | Mirror as needed | Local-first |
| Partner & investor collateral | English | Russian, Uzbek | Tailor to the partner; English for cross-border/investor |

## Multilingual rules

- **Don't half-translate.** If a page ships in a language, the headline, value prop, safety promise, and CTA must all be present in it — no English-only buttons on an Uzbek page.
- **Parity across the three primaries.** When a core asset is localized, UZ/EN/RU versions should carry the same message and offer — don't let one language lag with a weaker or outdated version.
- **Localize, don't just translate.** Adapt examples (venues, neighborhoods, holidays, names) so copy reads as written by a local, not machine-translated.
- **Keep brand terms stable across languages:** *Learnish*, *Learnish Club*, *Digital Club*, *Full Club* stay as-is; translate the surrounding description (e.g. "the Club" / "klub" framing) consistently.
- **Numbers and prices** follow local convention (currency, formatting) and stay consistent with the [monetization model](../pricing/monetization-model.md).

## QA workflow

1. **Draft in the lead language** for the audience/channel (per matrix above; default lead is Uzbek).
2. **Localize** into the other primaries (English, Russian) — adapt, don't literally translate.
3. **Native reviewer** validates meaning, tone, and age-appropriateness in each language (a fluent speaker, ideally a parent for parent-facing copy).
4. **Brand reviewer** confirms voice consistency and runs the [review rubric](../brand-review/review-rubric.md), including the localization-quality dimension.
5. **Log** the decision in the [review log](../brand-review/review-log.md); feed recurring translation issues back into this matrix monthly.

## Decided

- **Three primary languages, priority Uzbek → English → Russian.** Uzbek is the default first-touch lead; EN + RU produced alongside on core assets.
- **Latin Uzbek is the default script**; Cyrillic only on request for specific audiences/partners.
